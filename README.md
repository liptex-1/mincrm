# MiniCRM

Готовое приложение: `dist/index.html` — открывается двойным кликом, сервер не нужен. Данные — в IndexedDB браузера.

## Сборка и тесты
- `node build.mjs` — бандл React+TS (esbuild) в один HTML
- `tsx --test tests/finance.test.ts` — 26 тестов финансового ядра (сценарий из ТЗ, округление, авансы, возврат капитала, повторы, исторические распределения)

## Архитектура
- `src/domain` — чистая бизнес-логика без UI: `money` (копейки, метод наибольших остатков), `finance` (формулы), `ops` (операции → атомарный Batch), `analytics`, `demo`
- `src/db/storage.ts` — интерфейс `StorageAdapter` (IndexedDB / память). Для облака достаточно написать новый адаптер; все записи имеют `updatedAt`
- `src/store` — единая точка записи `mutate()`: правила → транзакция в БД → обновление UI. Нарушение правила = ничего не записано
- `src/pages`, `src/ui` — интерфейс

## Принятые решения
- Суммы — целые копейки; проценты — базисные пункты. Суммы выплат считаются по точным весам, проценты только для показа
- Выручка = полученные платежи − возвраты. Расход = `expense` + `advance`. Аванс партнёра не меняет кассу, создаёт долг
- Начисление прибыли — отдельная запись без движения денег; выплата — отдельная. Отмена распределения помечает записи `voided`, история остаётся
- Распределение хранит снимок долей, резерва и имён партнёров — позднейшие изменения настроек его не меняют
- Списание материалов идемпотентно: хранится фактически списанное (`consumed`), при сохранении применяется только разница
- Vite/Tailwind/Dexie/Recharts/Zustand не использованы: в окружении нет доступа к npm. Заменены esbuild, CSS-переменными, собственной обёрткой над IndexedDB, SVG-графиками и мини-хранилищем
